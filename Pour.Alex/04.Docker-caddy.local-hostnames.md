# Modular Docker: Refactoring Caddy
This tutorial shows how to separate Caddy into its own folder so it can manage MULTIPLE apps at once.

## Step 1: Create the Hallway
Run this in PowerShell to let different folder3 talk:
`docker network create caddy_network`

## Step 2: Update Vaultwarden
In `C:\Docker\vaultwarden`, remove Caddy from the file and add this to the bottom:
```yaml
networks:
  caddy_network:
    external: true
```

## Step 3: The Hosts Map
Add these to `C:\Windows\System32\drivers\etc\hosts`:
`YOUR_IP vault.local pdf.local kuma.local`

## Step 4: New Caddy Folder
Move your Caddyfile to `C:\Docker\caddy`. Caddy is now the "Manager" of the whole house.

## Why do this?
Now, when you add a new app in a new folder, you just tell it to join the `caddy_network` and Caddy will find it automatically.

## Step 5: The Caddyfile
In `C:\Docker\caddy\Caddyfile`:
```text
{
  default_sni YOUR_IP
}
vault.local {
  tls internal
  reverse_proxy vaultwarden:80
}
pdf.local {
  tls internal
  reverse_proxy stirling-pdf:8080
}
kuma.local {
  tls internal
  reverse_proxy uptime-kuma:3001
}
```
# Checking Your Work

### **Critical Reminder for Step 5**
When you write `reverse_proxy vaultwarden:80` in your Caddyfile, the name **vaultwarden** MUST match the `container_name` you wrote in that app's Docker Compose file.
